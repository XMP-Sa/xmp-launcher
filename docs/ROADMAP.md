## فاز ۱ — فورک و بیلد خام (بدون تغییر رفتار)

هدف: mtasa-blue بدون هیچ تغییر کارکردی، با نام XMP بیلد و اجرا شود.

1. ساخت ریپوی `xmp-blue` (فورک گیت‌هاب) و برنچ `xmp/main`
2. CI بیلد کلاینت روی `windows-latest`:
   - Visual Studio 2026 + Desktop C++ + MFC + DirectX SDK
   - `win-create-projects.bat` → بیلد `MTASA.sln` (Release, x86) → `win-install-data.bat`
3. CI بیلد سرور لینوکس با داکر رسمی آپ‌استریم (`linux-build.sh`)
4. تست دود (Smoke): اجرای کلاینت خام روی یک GTA SA تستی + اتصال به یک سرور عمومی MTA
5. برندینگ سطحی: نام خروجی‌ها، آیکون XMP، استرینگ‌های نمایشی، پوشه نصب و رجیستری XMP

**معیار پذیرش:** XMP Client خام به حداقل ۳ سرور عمومی شلوغ وصل شود و ۱۵ دقیقه بدون کرش بازی کند.
**ریسک اصلی:** سنگینی بیلد کلاینت (زمان CI + وابستگی DirectX SDK) — کاهش با کش بیلد گیت‌هاب.

## فاز ۲ — اتصال لانچر به کلاینت خودمون

هدف: کاربر فقط XMP Launcher را نصب کند؛ بقیه خودکار.

1. ماژول `client-manager` در لانچر (`electron/client.js`):
   - خواندن مانیفست آپدیت (`version`, `sha256`, `url`) از ریلیز گیت‌هاب
   - دانلود/نصب/آپدیت XMP Client در `client/` کنار لانچر، با نوار پیشرفت
2. ویزارد GTA SA: پیدا کردن خودکار + انتخاب دستی + اعتبارسنجی `gta_sa.exe`
3. تغییر `installer.js`: مسیر اجرایی از «MTA نصب‌شده» به «XMP Client داخلی» (قرارداد CLI همان قبلی)
4. حالت فالبک: اگر کاربر MTA رسمی دارد و کلاینت XMP هنوز دانلود نشده، پیشنهاد استفاده موقت از همان (اختیاری)
5. تست میدانی: نصب تمیز روی ویندوز ۱۰/۱۱ بدون MTA → اتصال به سرور عمومی

**معیار پذیرش:** روی یک ویندوز تمیزِ بدون MTA، از نصب XMP تا داخل بازی شدن ≤ ۳ کلیک (به‌جز انتخاب مسیر GTA).
