# معماری XMP مستقل — فورک mtasa-blue

> وضعیت: **سند طراحی (Phase 0)** — تصویب‌شده توسط تیم، قبل از شروع پیاده‌سازی
> تصمیم‌های پایه: فورک کامل MTA با برند XMP · فایل بازی با کاربر · اول طراحی، بعد اجرا

---

## ۱. هدف و تصویر کلی

XMP از یک «لانچر روی MTA نصب‌شده» تبدیل می‌شود به یک **پلتفرم مولتی‌پلیر مستقل**:

- کاربر فقط **XMP** را نصب می‌کند و یک نسخه قانونی از **GTA San Andreas** دارد.
- XMP خودش **کلاینت بازی (XMP Client)** را نصب، آپدیت و اجرا می‌کند — هیچ نصب جداگانه‌ای از MTA لازم نیست.
- XMP Client در فاز اول **کاملاً سازگار با پروتکل MTA** است: به همه سرورهای فعلی MTA وصل می‌شود.
- در فاز بعد، **سرورهای XMP** (فورک سرور MTA) اضافه می‌شوند و همان کلاینت به هر دو دنیا وصل می‌شود.

```text
┌──────────────────────────────────────────────────────────────┐
│  کاربر                                                       │
│   └─ GTA San Andreas (نصب‌شده توسط خود کاربر — توزیع نمی‌شود) │
└──────────────▲──────────────────────────────▲────────────────┘
               │ اجرا / اینجکت                 │ خواندن مسیر نصب
┌──────────────┴───────────────┐   IPC/CLI   ┌─┴─────────────────┐
│  XMP Client (فورک mtasa-blue) │◄───────────│  XMP Launcher      │
│  C++ · x86 · DirectX 9        │            │  Electron فعلاً،   │
│  core / game_sa / net / Lua   │            │  Tauri در آینده    │
└──────┬───────────────┬───────┘            └──┬────────────┬───┘
       │ پروتکل MTA    │ پروتکل MTA            │            │
       │ (بدون تغییر)  │ (بدون تغییر)          │ HTTPS      │ UDP/ASE
┌──────▼───────┐ ┌─────▼────────┐    ┌──────────▼───┐ ┌──────▼──────┐
│ سرورهای MTA  │ │ سرورهای XMP  │    │ مسترلیست MTA │ │ پینگ ASE    │
│ (عمومی، فعلی)│ │ (فورک سرور)  │    │ + API سرور XMP│ │ port+123   │
└──────────────┘ └──────────────┘    └──────────────┘ └─────────────┘
```

منبع: ریپوی رسمی [multitheftauto/mtasa-blue](https://github.com/multitheftauto/mtasa-blue)

| واقعیت | پیامد برای XMP |
|---|---|
| لایسنس **GPLv3** است (فایل `LICENSE` سورس) | XMP Client/Server باید GPLv3 بماند؛ با توزیع باینری، سورس متناظر باید در دسترس باشد. حذف کپی‌رایت‌های اصلی مجاز نیست. |
| کلاینت روی **کد اینجکشن و هوک** سوار است و فایل‌های اصلی بازی را تغییر نمی‌دهد | XMP هم همین کار را می‌کند؛ فایل GTA SA کاربر دست‌نخورده می‌ماند. |
| کلاینت **x86 (۳۲ بیت)** است چون gta_sa.exe ۳۲ بیتی است | بیلد کلاینت جدا از سرور است؛ لانچر باید هر دو را مدیریت کند. |
| بیلد ویندوز: **Visual Studio 2026 + Desktop C++ + DirectX SDK**، ساخت پروژه با `win-create-projects.bat` و Premake5، خروجی در `MTASA.sln` | بیلد کلاینت فقط روی ویندوز ممکن است → CI روی `windows-latest` گیت‌هاب. |
| سرور روی **لینوکس و ویندوز** بیلد می‌شود (`linux-build.sh` / Docker رسمی) | سرور XMP را می‌شود همین حالا در محیط لینوکسی بیلد و تست کرد. |
| ساختار: `Client/` (core, game_sa, multiplayer_sa, mods/deathmatch, sdk) · `Server/` · `Shared/` · `vendor/` | فورک باید همین ساختار را نگه دارد تا سینک با آپ‌استریم ارزان بماند. |
| گیم‌پلی با **Resource + Lua** ساخته می‌شود (متادیتا + آرشیو) | سرورهای XMP هم با همان سیستم Resource کار می‌کنند؛ گیم‌مود جدید لازم نیست از صفر نوشته شود. |

## ۳. اجزای سیستم

### ۳.۱ XMP Launcher (ریپوی فعلی — آماده)
- Electron فعلاً؛ معماری از اول Tauri-ready است (رندرر فقط از `window.xmp` حرف می‌زند).
- وظایف جدید در نسخه مستقل:
  1. **مدیریت کلاینت:** دانلود XMP Client از ریلیز گیت‌هاب، بررسی SHA-256، نصب در کنار خودش، آپدیت خودکار.
  2. **یافتن GTA SA:** رجیستری + مسیرهای رایج + انتخاب دستی؛ اعتبارسنجی `gta_sa.exe` (سایز/نسخه US 1.0).
  3. **اجرا:** اجرای XMP Client با آرگومان اتصال (به‌جای `Multi Theft Auto.exe` فعلی).
  4. **لیست سرور یکپارچه:** سرورهای MTA (مسترلیست فعلی) + سرورهای XMP (API خودمون) در یک لیست، با برچسب منبع.
- سرور لیست و پینگ ASE فعلی **بدون تغییر** باقی می‌ماند.

### ۳.۲ XMP Client (ریپوی جدید: `xmp-blue` — فورک mtasa-blue)
- فورک مستقیم از آپ‌استریم با ریموت `upstream` برای سینک دوره‌ای.
- تغییرات مجاز در فاز اول (سطحی و برگشت‌پذیر):
  - برندینگ: نام خروجی‌ها، آیکون، استرینگ‌های UI داخلی، مسیر نصب و کلیدهای رجیستری مخصوص XMP.
  - کانفیگ پیش‌فرض: مسترلیست/آپدیت‌سرور پیش‌فرض XMP، نیک‌نیم و تنظیمات اولیه.
- تغییرات **ممنوع** در فاز اول:
  - پروتکل شبکه و نسخه هندشیک (Net protocol version) — هر تغییری یعنی قطع شدن از سرورهای MTA.
  - سیستم سریال/شناسایی کلاینت و چک‌های سازگاری سرور — دست‌کاری آن‌ها ریسک کیک/بن از سرورهای عمومی دارد.
  - حذف یا جابه‌جایی اعلان‌های کپی‌رایت و لایسنس GPL.

### ۳.۳ XMP Server (همان فورک، خروجی سرور)
- نوع سرورهای خودمون **فعلاً نامشخص** بود؛ پیشنهاد طراحی (تصمیم پیش‌فرض):
  **XMP Server = فورک سرور MTA با پروتکل یکسان.** دلیل: یک کلاینت برای هر دو دنیا، گیم‌مودهای آماده Lua/Resource، هزینه نگهداری کم.
- تغییرات سرور: برندینگ کنسول و نام پروسس، کانفیگ پیش‌فرض (نام سرور، مسترلیست)، قابلیت رجیستر شدن در API سرورهای XMP علاوه بر مسترلیست MTA.
- اگر بعداً پروتکل اختصاصی خواستیم، آن تصمیم یک ADR جدا می‌خواهد و یعنی جدایی کامل از سرورهای MTA (در ROADMAP به‌عنوان شاخه اختیاری آمده).

### ۳.۴ سرویس‌های آنلاین XMP (سبک، بعداً)
- `api.xmp.*` ساده روی یک هاست ارزان: لیست سرورهای XMP تأییدشده + فایل مانیفست آپدیت کلاینت (نسخه + SHA-256 + URL ریلیز گیت‌هاب).
- بدون دیتابیس سنگین در شروع: JSON استاتیک یا یک سرویس کوچک؛ لانچر همین حالا هم با JSON استاتیک کار می‌کند.

## ۴. چرخه اجرا (Launch Flow)

```text
1. کاربر سرور را انتخاب می‌کند (MTA یا XMP — برای کلاینت فرقی ندارد)
2. لانچر بررسی می‌کند:
   ├─ GTA SA پیدا شد؟        نه ← ویزارد انتخاب مسیر
   ├─ XMP Client نصب است؟    نه ← دانلود + نصب (یک بار)
   └─ نسخه کلاینت به‌روز است؟ نه ← آپدیت دلتا/کامل از ریلیز
3. لانچر XMP Client را با --connect ip:port (و رمز/نیک‌نیم) اجرا می‌کند
4. کلاینت gta_sa.exe را لود و DLLهای XMP را اینجکت می‌کند
5. اتصال با همان پروتکل MTA برقرار می‌شود
```

قرارداد اجرا (CLI) عمداً با MTA سازگار می‌ماند تا کد فعلی لانچر (`electron/installer.js → buildArgs`) با کمترین تغییر به باینری جدید وصل شود: فقط مسیر اجرایی عوض می‌شود.

## ۵. استراتژی فورک و سینک با آپ‌استریم

- ریپوی `xmp-blue` فورک گیت‌هابی از `multitheftauto/mtasa-blue`؛ برنچ `xmp/main` برنچ کاری ماست، `master` آینه آپ‌استریم.
- سینک: ماهانه (یا با هر ریلیز پایدار MTA) مرج آپ‌استریم → تست سازگاری → ریلیز.
- قانون طلایی: **هر تغییر ما باید در کمترین فایل ممکن و پشت کامیت‌های جدا باشد** تا مرج آپ‌استریم ارزان بماند. تغییرات برندینگ در لایه‌های سطحی (resourceها، استرینگ‌ها، کانفیگ) نه در قلب شبکه.
- پچ‌های ما در `docs/patches/` ریپوی فورک مستند می‌شوند (هر پچ: دلیل + فایل‌ها + ریسک سینک).

## ۶. لایسنس، قانون و ریسک‌ها

| موضوع | وضعیت / اقدام |
|---|---|
| **GPLv3 فورک** | XMP Client/Server متن‌باز با GPLv3 منتشر می‌شود؛ صفحه ریلیز باید لینک سورس متناظر همان نسخه را داشته باشد. لانچر Electron (کد خودمون) می‌تواند جدا بماند چون پروسس جداست و از CLI/IPC حرف می‌زند، نه لینک باینری — ولی برای سادگی و شفافیت پیشنهاد می‌شود آن هم با همان ریپو/لایسنس شفاف منتشر شود. |
| **فایل‌های GTA SA** | هرگز توزیع نمی‌شود. کاربر بازی را خودش دارد؛ لانچر فقط مسیر را پیدا و اعتبارسنجی می‌کند. |
| **نام و برند MTA** | XMP محصول مستقل است؛ در UI و README سلب وابستگی رسمی می‌آید (همین حالا در لایسنس لانچر هست). از لوگو/نام MTA به‌عنوان برند خودمون استفاده نمی‌شود. |
| **مسترلیست MTA** | استفاده فعلی (خواندن لیست عمومی + ASE) ادامه دارد؛ سرورهای XMP بعداً API خودشان را هم دارند تا وابستگی کامل نباشد. |
| **سازگاری با سرورهای عمومی** | بعضی سرورها چک فایل/سریال دارند؛ چون در فاز اول هسته دست‌نخورده است، ریسک کم است — ولی تضمینی نیست و در تست میدانی (ROADMAP فاز ۲) باید با چند سرور بزرگ راستی‌آزمایی شود. |
| **امضای دیجیتال** | اینستالر و باینری‌های کلاینت فعلاً بدون Code Signing هستند (هشدار SmartScreen)؛ برای انتشار عمومی جدی، تهیه سرتیفیکیت در نقشه راه آمده. |

## ۸. تصمیم‌های باز (قبل از فاز ۲ باید بسته شوند)

1. نام باینری‌ها و مسیر نصب نهایی کلاینت (`XMP Client.exe`؟ پوشه `XMP/Client` کنار لانچر یا جدا؟) — پیشنهاد: کنار لانچر، زیرپوشه `client/`.
2. کانال آپدیت کلاینت: ریلیز گیت‌هاب (پیشنهاد شروع) یا هاست جدا.
3. آیا XMP Server از روز اول در مسترلیست MTA هم رجیستر شود یا فقط API خودمون؟ — پیشنهاد: هر دو.
